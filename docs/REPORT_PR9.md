## 3. Доработка индивидуального проекта

Продолжен исходный проект ip_fr. Сохранены приложения records, collections_app, homepage, прежние URL, базовые шаблоны и консольная версия прошлых практических. Для исходной сущности пользователя добавлено приложение users.

| Модель | Поля и назначение |
| --- | --- |
| Record | id, title, artist, genre, year - пластинка. |
| Collection | id, name; records - многие ко многим через CollectionRecord. |
| User | id, name, email - пользователь предметной области, отдельно от Django Auth. |
| CollectionRecord | id, collection, record - два ForeignKey; уникальная пара ссылок. |

Идентификаторы - BigAutoField. Текстовые поля - CharField(255), email - EmailField(254), год - PositiveIntegerField. Неизвестный год сохраняется как 0/NULL; известный проверяется в пределах 1900-текущий год. Для жанра разрешены пустое значение и NULL. Настроены __str__, обратные имена связей и CASCADE для строк связи. Удаление коллекции сохраняет пластинки. Связь владельца не добавлялась: в исходной базе её нет.

Созданы и применены 0001_initial в records, collections_app и users. Все модели зарегистрированы в admin; состав коллекции редактируется вложенными строками. Команда demo_orm демонстрирует create/get/save/delete и всегда откатывает учебные изменения.

## 4. Стратегия перехода и сохранность данных

Выбран вариант 2: Django создаёт таблицы в db.sqlite3; data/vinyl.sqlite остаётся источником только для чтения, сохранена резервная копия. Команда import_pr7 валидирует данные и записывает их через ORM в transaction.atomic(). Идентичный повтор не добавляет дубликаты; конфликт или битая ссылка отменяет всю операцию.

Перенесено **10 пластинок, 5 коллекций, 2 пользователя и 13 связей**. Сверены все значения, исходные ID и пары внешних ключей; источник и резервная копия совпадают побайтно. Для чистой установки сохранена fixture data/orm_fixture.json с 30 объектами.

## 5. ORM, страницы и результат

Представления каталога, поиска, карточек, коллекций и статистики переведены на ORM. Реализованы 16 отдельных рабочих выборок; цепочка фильтров одного каталога считается одной выборкой. Полный реестр приведён в docs/ORM_QUERIES.md.

Реализованы получение объектов, фильтры по жанру, годам и связанному исполнителю, exclude неизвестных лет, поиск по одному и нескольким полям, сортировка, values_list, select_related и prefetch_related. Статистика использует Count, Min, Max, Avg, aggregate и annotate. Таблица состава коллекций получает связанные поля через F() и values().

Paginator выводит по 5 объектов. Тег querystring сохраняет параметры при переходах; новая отправка формы сбрасывает номер страницы. Django Forms проверяют входные данные, пустые результаты обрабатываются, отсутствующие карточки возвращают 404. Пустые коллекции не теряются. README описывает модели, миграции, импорт и запуск. Для просмотра SQL подключён Django Debug Toolbar; панель доступна локально в DEBUG.
